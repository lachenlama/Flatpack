# WP5c Report: Assemble, Portfolio, Flywheel

Status: delivered and verified against the local rehearsal fork (port 8547, `rehearsal-8547`, app on 3001, `NEXT_DIST_DIR=.next-c`). Only `web/src/app/{assemble,me,flywheel}/**` and this file were touched.

## What was built
- **/assemble** (five numbered steps, `AssembleForm.tsx`, server data in `data.ts`): token picker (only registry-enabled components, price and feed age, "stale" label past 4 days, ticker search); weights with live `BarList` and sum-to-100 check; name, symbol and dividend mode with inline validation; preview (30-day **hypothetical** recipe backtest vs SPY via WP5a `history.ts` through `/assemble/preview`, "one share ≈ $100", units table from `rawUnitsFor`); stake and publish through `TxButton` (① approve exactly the stake in WIF to the **factory**, ② `createBasket`). The publish step re-reads the Chainlink prices and recomputes units at click time, then simulates itself so factory errors (`BadName`, `BadSymbol`, `StakeTooLow`, `ComponentDisabled`, `ZeroUnits`, ...) show on the field they concern (`plan.ts fieldForError`). On success: a "Published" panel with a Share on X link, then a redirect to `/b/<new>?created=1` after 2.5 s (the `created=1` param is there for WP5b if it wants a celebration).
- **/me** (`Portfolio.tsx`, `data.ts`, `referral.ts`, `/me/data` JSON route): positions table (shares, value, $WIF backed, vs SPY) plus **Claim everything** and one card per source with a one-line "why you have this": $WIF dividends (`claimWifDividend`), backing rewards (`vault.claim`), curator rewards (`vault.claimCurator`), referral $WIF (iterates `0..currentCycle-1` with `referralOf`, claims only unclaimed cycles with amount > 0 via `claimReferral`), IOUs (`claimIOU` per token). `/me?address=0x...` server-renders any account read-only; with a connected wallet it fetches `/me/data` and refreshes after each claim.
- **/flywheel** (`page.tsx`, `FlywheelDiagram.tsx`): hero total $WIF burned and $WIF bought; six KPI tiles (curators, backers, referrers, dividends, TVL, buy volume) each with a source tooltip naming the event it sums; an SVG flywheel with live numbers on the edges (and an accessible `<desc>`); feed of the latest 20 events with Blockscout tx links.
- Copy follows §7 (Stock Tokens, Robinhood Chain, "hypothetical", no invest/returns/profit).

## Honest notes / not verified
- **Fork-state expiry (environment, not app):** the upstream RPC stops serving state at the fork block after some minutes ("historical state ... is not available", surfaced by EDR as "Missing or invalid parameters"). Any read or write of a mainnet-contract storage slot that was never touched locally then fails (it hit `WIF.allowance(#3, factory)` and the Chainlink history reads). The first rehearsal went stale mid-task; I re-ran it and executed set-up, build and UI test within minutes. `touch-allowance.ts` writes that allowance slot early for this reason. A real chain is unaffected. The rehearsal node also died once right after `REHEARSAL OK` when launched with a short-lived `wsl.exe` session; launching it inside a `bash -c '... & sleep'` session worked.
- The first-time `/assemble/preview` for a new recipe can take several seconds (Chainlink round bisection, cached 10 minutes). When a feed has too little history the page says so instead of drawing (seen once for an AAPL recipe while the fork state was expiring; unverified whether it is only that).
- The WP5a attestation modal ("Before you connect") overlays pages in the headless run; the mock wallet still transacts, so the click-through does not exercise accepting it.
- Real extension wallets, chain switching, mobile layout and keyboard/Lighthouse checks were not exercised. Chart hover interaction is not browser-tested. Curator rewards and backing rewards cards were only verified in the empty state (no settle with a beat happened on the fork); their claim steps are built the same way as the verified referral one but not executed. The IOU card was not exercised either.
- `createBasket` UI redirects to `/b/<new>?created=1`; the share prompt itself is on the assemble success panel (WP5b owns `/b/[address]` and was not changed).
